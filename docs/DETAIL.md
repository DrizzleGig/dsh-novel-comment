# dsh-novel-comment（AI 读者）详情

## 一句话

给作者一屋子「只读到这一章」的 AI 读者：他们按口味读稿、打星、写章评/段评，各自记忆互不相通。

## 它解决什么

- **上帝视角诅咒**：作者知道后文，容易高估铺垫。读者只有前文记忆，该困惑就困惑。
- **读者会弃书**：追更读者有耐心阈值与疲劳计数，能说「这里我会划走」。
- **不同读者口味相反**：多读者并排，分歧本身就是修改信号。
- **改稿后意见失效**：改稿会让该章及以后的评审链失效，重评必须按序。

## 怎么用

1. 右栏「AI 读者」页签打开面板；或在会话里用 `reader_books create` 建读者（模板 binge/emotion/plot，或自建人设 + 喜好/雷点标签）。
2. `reader_books import` 导入你的章节（按 `sequenceNumber` 排序），面板「当前作品」也能看到正文。
3. 配置 `READER_LLM_BASE_URL` / `READER_LLM_MODEL`（可选 Key）后，`reader_review` 让读者评第 1 章；之后必须按序评第 2、3 章。
4. 面板里可直接 1–5 星 + 章评 + 段评 + 追更/观望/弃书；`reader_rate` 也能手工补一条。
5. `reader_report` 生成当天日报；面板「找书」可按六类标签搜索（`READER_SOURCE=fake` 演示），也可按读者口味推荐。
6. 面板右上角四档底色（纸白/米黄/护眼绿/夜间）随点随换，刷新后保持。

## 数据与边界

- 数据目录：`<工作区>/.dsh-novel-comment/`（读者、口味、评分、记忆、配额、日报）；全局读者索引在 `<DSH_HOME>/dsh-novel-comment/`。
- 只读「读者已读到的前文 + 本章正文」，不注入后文；读者记忆独立于作者记忆（fade 是另一套）。
- 不写其他 `.dsh-novel-*` 目录；不训练模型；评分与日报不含外部作品正文。
- 公开网页导入只保存 ≤300 字摘录；付费墙/验证码/风控会停止并提示。

## 配置

| 变量 | 说明 |
|---|---|
| `READER_LLM_BASE_URL` | OpenAI 兼容端点（如 `https://api.deepseek.com/v1`） |
| `READER_LLM_MODEL` | 模型名 |
| `READER_LLM_API_KEY` | Key（不落盘、不进日志） |
| `READER_SOURCE=fake` | 启用内置假书源演示找书 |
| `READER_PAGE_HOSTS` | 逗号分隔的公开页域名白名单（L2 导入） |

未配置模型时 `reader_review` 明确报错（`model-not-configured`），不会静默生成假评分。

## 已知限制（0.5.1）

- 真实书源（番茄等）未接入；`reader_discover` 目前只有假书源。
- 真实站点抓取（L1/L2）未验证；内置假书源只用于演示。
- 真实模型调用需自备端点/Key；发布验证用脚本化模型端口，未做真实 API 调用。
- 真实 DSH 宿主、真书、真实站点/登录态验证按工作区规则后置。
